**P03 · YouCam Skin Analysis client (4 steps) with mocks + in-memory imaging** · Cursor★ (or CC + R review) · Context: `AGENTS.md` (YouCam section), plan §5 and §5.1 · ~1.5 h
> Write `src/skinledger/imaging.py` and `src/skinledger/youcam.py`; `youcam.py` is the only module that reads `YOUCAM_API_KEY`. Use `httpx.AsyncClient` (30 s timeout for JSON, 120 s for the PUT). Everything below was verified in the official docs on 26 Oct except where marked:
> 0. **`imaging.prepare(data: bytes) -> PreparedImage(bytes, content_type, width, height)`**, pure and in memory (`io.BytesIO` only; never `tempfile`, never `Image.save(path)`): open with Pillow, accept only JPEG/PNG, reject > 10 MB or short side < 480 px with `ImageRejected(code="error_exceed_max_image_size" | "error_below_min_image_size" | "unsupported_format")` before any API call (no units, no requests). Apply `ImageOps.exif_transpose`, drop all EXIF/metadata, and re-encode to JPEG quality 92 in memory (if the re-encode exceeds 10 MB, lower quality to 85). Guard against decompression bombs (`Image.MAX_IMAGE_PIXELS` set to ~40 MP; catch `DecompressionBombError` → `unsupported_format`).
> 1. **Headers:** `Authorization: Bearer {key}` and `Content-Type: application/json` on JSON calls. If the key is missing and `YOUCAM_MOCK` is false, raise `YouCamConfigError("YOUCAM_API_KEY is not set")` with no further detail.
> 2. **`upload_file(img: PreparedImage, file_name="capture.jpg") -> str`:** `POST {base}/s2s/v2.0/file` with `{"files":[{"content_type": ct, "file_name": name, "file_size": len(bytes)}]}`. Read `data.files[0].file_id` and `data.files[0].requests[0]` (`method`, `url`, `headers`). Do the `PUT` (or the returned `method` if it differs) to `url` with **exactly** the returned `headers` (they include Content-Type and Content-Length) and the bytes as the body, **without** the Authorization header (it's a signed URL). Return `file_id` as `str`. The function takes bytes from memory and never touches the filesystem.
> 3. **`create_task(file_id: str, actions=SD_ACTIONS, mask_overlay=False) -> str`:** `POST {base}/s2s/{YOUCAM_SKIN_VERSION}/task/skin-analysis` with `{"src_file_id": file_id, "dst_actions": [...], "format": "json"}`; if `mask_overlay`, add `"miniserver_args": {"enable_mask_overlay": true}` (default **false**: we want per-aspect masks, not the photo with an overlay). Reject locally any action prefixed `hd_` or outside `SD_ACTIONS` (the server would answer 400 "cannot mix HD and SD dst_actions" / "Not available dst_action"). Return `data.task_id` as `str`. The default version is `v2.0`; `v2.1` appears in the units table and in the official repo `YouCam-API/skills`, but what changes is **[unverified]**: don't use it unless Francisco asks.
> 4. **`get_task(task_id) -> TaskResult`:** `GET {base}/s2s/{version}/task/skin-analysis/{task_id}`. `data.task_status` ∈ `running | success | error`. On `success`, `data.results.output[]` has, per aspect, `type`, `ui_score`, `raw_score`, `mask_urls`. **Drop `ui_score` right here** (it never leaves the parser). **[unverified]:** the shape of `skin_type` (may be categorical, with subfields such as whole/t_zone/u_zone), of `all` and of `skin_age`, and which field carries the error code when `task_status == "error"` (look in `data.error`, `data.error_code`, `data.results.error`, in that order; if none, use `"unknown_task_error"`). Parse tolerantly: unknown aspects are kept in the raw JSON and logged with `# UNVERIFIED`, they never crash. Return `TaskResult(status, scores: dict[str, float|None], categorical: dict[str,str], mask_urls: dict[str, list[str]], error_code, raw: dict)` where `raw` is the JSON without `ui_score` and without signed URLs.
> 5. **`poll(task_id, interval=YOUCAM_POLL_INTERVAL_S, timeout=YOUCAM_POLL_TIMEOUT_S)`:** check every 5 s (what the official repo uses; the docs only say "periodically") until `success`/`error`; at the timeout return `status="timeout"` **without** losing the `task_id` (valid 30 days; the pipeline resumes it). Never stop checking a running task for more than a few minutes: the FAQ says polling a "timed out" task returns `InvalidTaskId`.
> 6. **`download(url) -> bytes`** for masks, without the Authorization header. On 403/404/expired, call `get_task(task_id)` once to get fresh URLs (the URL lasts 2 h; the task 30 days) and retry.
> 7. **Retries and limits:** 429 → exponential backoff with jitter (1, 2, 4, 8 s, max 4 attempts), honouring `Retry-After` if present; the limit is 250 requests / 300 s per IP and per token (~5 QPS). 5xx and network errors → 2 retries only for GETs and the PUT; **never** retry `create_task` automatically (it could charge twice) unless the response was 429. A global semaphore of 1 analysis at a time.
> 8. **Errors → typed exceptions and an English user message** in a `FRIENDLY_ERRORS` dict:
>    - `error_src_face_too_small` → "Move closer: your face should fill most of the frame."
>    - `error_src_face_out_of_bound` → "Center your whole face inside the frame."
>    - `error_lighting_dark` → "Too dark. Face a window or a soft light and try again."
>    - `error_below_min_image_size` / `error_exceed_max_image_size` / `exceed_max_filesize` / `unsupported_format` → "This photo can't be used. Please upload a JPG or PNG under 10 MB, at least 480 px on the short side — or use the guided camera."
>    - `error_no_face` → "We couldn't find a face. Use a front-facing photo of your own face."
>    - `error_large_face_angle` → "Keep your head straight and look at the camera."
>    - `error_multiple_people` → "Only one person should be in the photo."
>    - `error_decode_image` / `error_download_image` → "The photo couldn't be read. Please try another one."
>    - `error_face_parsing` / `error_inference` / `unknown_internal_error` / `unknown_task_error` → "The analysis service had a problem. No units were charged. Try again in a minute."
>    - HTTP 400 `InvalidParameters` → programming error (log, generic message). HTTP 401 `InvalidAccessToken` → "Analysis is temporarily unavailable." and log "check YOUCAM_API_KEY" (without the key). `InvalidTaskId` → mark the capture `error` with `error_code="InvalidTaskId"`.
>    Image codes come from the Skin Analysis reference; general ones from `/develop/error_codes` [verified 26 Oct]. None of these `error`s consumes units. All image-error messages end with "This attempt didn't count toward your limit." when shown to a visitor.
> 9. **Balance (optional, for /admin/usage):** `get_credit_balance()` → `GET {base}/s2s/v1.0/client/credit`, sum `amount` over `results[]` whose `type` starts with `"Api"`. **[official repo, not in the docs]**: on failure return `None` and the UI uses the local `api_usage` counter.
> 10. **Mock mode** (`YOUCAM_MOCK=true`): same interface, no network, returns the fixture `tests/fixtures/sd_result_SAMPLE.json` (marked `"_label": "SAMPLE"`) with 2 `running` states before `success`, and grey PNG masks generated in memory. Write the fixture **from the structure of the docs example** (`results.output[]` with `type`, `ui_score`, `raw_score`, `mask_urls`), with round, obviously-sample numbers and a comment saying it is SAMPLE.
> 11. Never print headers, the key or request bodies; in logs, mask signed URLs (`?…` → `?<signed>`).
